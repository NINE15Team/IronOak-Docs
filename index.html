Iron OakTheme documentation

Iron Oak theme overview

How the Iron Oak Apparel storefront is built, and where to go to change it. Written for the people who run the store day to day and the developers who maintain it.

What this site is

Iron Oak Apparel sells western pearl snap polos, hoodies, hats and belts. The storefront runs on Shopify using Shopify's Horizon theme (version 4.1.5), customized by Nine15 to match the Iron Oak design. Almost every page is assembled in the Shopify theme editor out of Horizon sections and blocks, so most content changes need no code.

Key features

  • One product per color. Each colorway is its own product. Color "swatches" on the product page link between those products. See Swatches.
  • Collection-aware product pages. The breadcrumb, swatches and links remember which collection the shopper came from. See Breadcrumbs.
  • Reserve mega menu. A custom Shop menu with a signature Polos panel and three feature cards, all driven by Shopify menus and block settings. See Navigation & mega menu.
  • Vertical filter rail with chips, color swatches, a hide-rail toggle and a "Ask our chat" note. See Filters.
  • Size chart page powered by a metaobject, with a size finder and IN/CM toggle. See Metaobjects.
  • Contact and store locations with live open/closed status in Central Time. See Pages.
  • Apps for reviews (Judge.me), email/SMS (Klaviyo, Alia), cart and AI chat (Slide), search (Ryzo), fit advice (WAIR) and gifting (Gifted). See Apps & integrations.

Theme architecture

How the theme files fit together, and the three building blocks you see in the editor: templates, sections and blocks.

Folder structure

FolderWhat lives there

blocks/Theme blocks that go inside sections: text, group, button, variant-picker, filters… Files starting with _ are private blocks used only by one parent section.

layout/theme.liquid (the HTML shell for every page) and password.liquid.
locales/Translations and editor labels.
docs/This documentation. Shopify ignores this folder.

Templates, sections and blocks

A page is a template. A template is a stack of sections. A section holds blocks, and the group block can hold more blocks, so layouts nest as deep as needed.

templates/product.json
└─ section: product-information       (main product area)
   ├─ _product-media-gallery           (static block: photos)
   └─ _product-details                 (static block: right column)
      ├─ group "breadcrumb" → text
      ├─ group "header" → text (title), price, Judge.me badge
      ├─ variant-picker                (swatches + sizes)
      ├─ buy-buttons → quantity, add-to-cart, accelerated-checkout
      └─ group "description" → text {{ closest.product.description }}
└─ section: media-with-content        (feature callout)
└─ section: section "Reviews"         (Judge.me widget app block)
└─ section: product-list              (Shop Our Best Sellers)

The header and footer are section groups. They appear on every page and are edited from any page in the editor:

  • sections/header-group.json: announcement bar, header (logo + Reserve mega menu).
  • sections/footer-group.json: newsletter, footer menus, utilities (copyright, policies), tagline.

How we build pages

The theme follows one rule: compose with Horizon sections and blocks, do not write new sections. Where Horizon was missing a control, we added settings to the existing section (for example mobile padding, promo tile, sibling swatches) instead of forking it. This keeps every page editable in the theme editor and keeps the theme upgradeable.

Notecustom-liquid blocks are used only for scripts and app glue (for example the contact page script and the size chart). They are not for layout.

Deploy, backup & workflow

How changes move between the theme editor, GitHub and the live store, and how to roll back safely.

How the theme is connected

The live theme is connected to the GitHub repo NINE15Team/IronOak through Shopify's GitHub integration. The sync runs in both directions:

  • Editor → GitHub. When someone saves in the theme editor, Shopify commits the change to the connected branch. These show up as commits named "Update from Shopify for theme …".
  • GitHub → Store. When a developer pushes to the branch, Shopify updates the connected theme within a minute or two.
Watch outBecause both sides write to the same branch, a developer must pull before pushing. Pushing an old copy of a template overwrites editor changes made since.

Branches

BranchRole
mainProduction history.
final-copyLaunch working branch, connected to a theme in Shopify.
Feature branchesConnect them to an unpublished theme to preview, then merge.

Check Online Store → Themes to see which theme is connected to which branch.

Local development

Developers use Shopify CLI from the theme folder:

shopify theme dev --store iron-oak-apparel-co

This serves a live-reloading preview of local files against real store data. Changes made in the editor during theme dev are written back to the local files. To pull the latest editor changes without the GitHub sync:

shopify theme pull --store iron-oak-apparel-co --theme <theme-id>

Backups & rollback

  1. Before big changes, go to Online Store → Themes → ⋯ → Duplicate on the live theme. The copy is a full backup you can publish in one click.
  2. To restore one file, find the commit in GitHub before the change and revert it, or use Edit code → [file] → Older versions in Shopify.
  3. To restore everything, publish the duplicate you made, or connect a theme to an older commit.
NoteProducts, collections, metafields, menus and pages are store data, not theme files. Theme backups do not include them. Export products from Products → Export if you need a data backup.

Domain & SSL

Shopify issues and renews SSL certificates automatically for every connected domain. Domains are managed in Settings → Domains. Nothing in the theme needs to change when a domain or certificate changes.

Using the theme editor

Most content lives in sections and blocks. This page covers the editor basics and the Horizon patterns used across the site.

Open the editor

  1. Go to Online Store → Themes and click Customize on the theme.
  2. Use the page picker at the top to switch template (e.g. Products → product.hats).
  3. The left panel lists sections and their blocks. Click one to edit its settings on the right.
  4. Click Save. The change is live (and committed to GitHub) right away.

Add, move and hide

  • Add a section: Add section at the bottom of a template, or between sections. Prefer Section, Product list, Media with content, Hero or Carousel.
  • Add a block: Add block inside a section or group. Use Group to make rows and columns, then Text, Button, Image, Icon inside.
  • Reorder: drag the handle beside a section or block.
  • Hide: click the eye icon. Hidden sections stay in the template (e.g. the old Reviews carousel on the home page) and can be turned back on later.

Groups do the layout

A Group block arranges its children in a row or column. Its settings control direction, alignment, gap, width, padding (desktop and mobile), background and border. Iron Oak added three group settings:

SettingWhat it does
Stack below widthStacks a row into one column when the group is narrower than this width, at any screen size. Width must be Fill. 0 turns it off.
Minimum height / mobileKeeps tiles in a row the same height.
Custom classA CSS hook for developers. Some scripts rely on it (see Contact page). Do not rename these classes.

Dynamic sources

Text settings can pull live data instead of fixed copy. Click the Connect dynamic source icon beside a field, or type Liquid-style references directly. Examples used in the templates:

ReferenceShows
{{ closest.product.title }}The current product's title (PDP heading, breadcrumb).
{{ closest.product.description }}The product description.
{{ closest.collection.title }}The current collection's title (collection banner).
{{ closest.collection.description }}The collection description.
{{ settings.color_palette.bronze }}A theme palette color. Used in color settings so a palette change updates every section.

To show a metafield, connect it as a dynamic source. The PDP has an empty Eyebrow (connect a metafield) text block in the header group ready for this.

Padding on desktop and mobile

Every section has Padding → Top / Bottom plus separate mobile values. Change spacing here, never with custom CSS: CSS overrides these settings and makes them look broken.

How the Shop mega menu is built

  1. The main menu item named in Menu item that opens the shop mega menu (currently Shop) opens the mega menu.
  2. Its children named in First column groups (currently Start here, Featured collections) stack in the first column. Each child is a heading and its own children are links.

  4. The remaining Shop children stack after the panel.
  5. Three feature cards sit on the right. Each has image, eyebrow, heading, text, link label and link. If image or link are empty, the card uses the chosen Collection's image and URL.

Any other main menu item with children (e.g. Discover) opens a simpler columns menu.

Breadcrumbs

Breadcrumbs are ordinary Text blocks, so you edit them like any other copy. The product page version knows which collection the shopper came from.

Product page breadcrumb

In every product template: Product information → Product details → breadcrumb → crumb. The text is:

<a href="/">Home</a> / [collection_link] / {{ closest.product.title }}
Shopper arrives fromURLBreadcrumb
A collection grid or product list/collections/western-yoke/products/the-hollowHome / Western Yoke / The Hollow
Search, an email, a direct link/products/the-hollowHome / Shop / The Hollow

How collection context is kept

  • Product cards in collection grids and product lists link with the collection in the URL (Liquid within), so the next page knows where the shopper came from.
  • Sibling swatches on the PDP keep the same collection in their links, so switching color does not lose the breadcrumb.
  • Canonical URLs still point to /products/…, so this does not create duplicate pages for SEO.

Collection page breadcrumb

In collection templates: Collection banner → Content → Breadcrumb.

<a href="/">Home</a> / <a href="/collections/all">Shop</a> / {{ closest.collection.title }}

The middle step is a fixed link. Change the text or URL in the block if needed.

How products are set up

The catalog has one rule that everything else depends on: each color is its own product, and sizes are its variants.

Products, families and siblings

  • Product: one colorway, e.g. The Hollow. Variants are sizes (XS–4XL).
  • Family collection: all colorways of one style, e.g. western-yoke, the-original-pearl-snap-polo, vintage-collection.
  • Siblings: the other products shown as color swatches on the product page. They come from the collection the shopper is browsing, or from the product's metafields.

Checklist for a new product

  1. Create the product with a Size option (the option must be named Size for size carry-over and the size chart link).
  2. Add photos. The first image is the card image; the second is the hover image.
  3. Pick the Theme template (polos use the default; see Sitemap).
  4. Add it to its family collection and any merchandising collections (best-sellers, new arrivals…).
  5. Set metafields: custom.sibling_collection, custom.parent_collection, and custom.print (swatch image). See Metafields.
  6. Set the product category and Color so filters and swatches pick it up. See Filters.
  7. Check the product page: swatches, breadcrumb, size chart link, reviews badge.
Developer neededThe PDP feature callout photos are mapped per product handle in snippets/io-polo-callout-photo.liquid. A new product shows the section's default images until a developer adds it to that map.

Product: sibling_collection & parent_collection

These tell the product page which products are its colors when the shopper did not arrive from a collection.

  • Set sibling_collection to the product's family, e.g. Western Yoke.
  • Set parent_collection to a broader collection whose products should also appear, or the same family. The theme de-duplicates.
  • The product card "N colors" label counts sibling_collection (or parent_collection if empty) products.

Product: print

A close-up image of the fabric. It becomes the round/square swatch on sibling swatches. Without it, the swatch uses the product's featured image, which usually looks worse at swatch size. A product with neither image is skipped.

Collection: description_more

Long copy for SEO or story that should not push the grid down. The collection description shows first; this field sits in a collapsed Read more + below it.

Add or edit a metafield value

  1. Open the product, collection or page in admin.
  2. Scroll to Metafields at the bottom and click the field.
  3. Pick the collection / upload the image / choose the entry, then Save.
Bulk editSelect many products, click Bulk edit, then add the metafield columns to set sibling_collection for a whole family at once.

Show a metafield on the page

Any text block can show a metafield: click Connect dynamic source and pick it. To show one on every product, edit the product template once (e.g. the PDP Eyebrow block).

Metaobjects

Metaobjects are reusable content entries. The theme uses one: Size chart, which fills the size chart page.

M | 28 3/4 | 41-42 | 9 3/4 | 170-185

Build a size chart page for another product type

  1. Create a new Size chart entry, e.g. Hoodies, and fill the fields.
  2. Create a page, e.g. Hoodie size chart, with template page.size-chart.
  3. On the page, set metafield custom.size_chart to the new entry.
  4. On the product template, in Variant picker → Size chart → Page, choose the new page. The link opens the chart in a dialog.
FallbackIf the page has no entry linked, it shows the built-in adult polo chart and FAQs, so the page is never empty.

Sibling swatches

Because each color is its own product, the variant picker shows the other color products as image swatches. Clicking one goes to that product.

Where the siblings come from

  1. From a collection (URL has /collections/…/products/…): show that collection's products, up to 24, and keep the collection in each link.
  2. From /collections/polos: that collection is the whole catalog, so the theme swaps it for best-sellers if the product is in it. If not, it uses parent_collection when that is a family collection, otherwise the first family collection the product belongs to.
  3. No collection (search, email, direct link): products from sibling_collection, then parent_collection, up to 50 each, without duplicates.

Family collections recognized on the polos special case:

the-original-pearl-snap-polo, western-yoke, vintage-collection,
oak-washed-denim-collection, refined-plaid-collection,
signature-solids-collection, the-heritage-collection, the-buckaroo-collection
Developer neededThis list lives in snippets/variant-main-picker.liquid. A new polo family needs to be added there to work from /collections/polos.

Rules

  • Swatch image: custom.print, else the featured image. Products with neither are skipped.
  • The row only shows when there are at least 2 siblings.
  • Size carry-over: if a size is selected, each swatch link includes that size's variant on the sibling product, so switching color keeps the size.
  • The current product's swatch is marked selected.

Color swatches are squares sized by theme settings (Theme settings → Swatches) and are all the same size. Size buttons match the Add to cart height. See Developer rules.

SEO & content best practices

What the theme does automatically, and what to do when adding content.

Handled by the theme and apps

  • Collections and pages without their own SEO description get a generated one (e.g. "Shop Western Yoke at Iron Oak…"), so no page goes out with a blank description.
  • Open Graph / social tags and structured data (product, organization). Yoast SEO adds its own meta tags.
  • Canonical URLs on products point to /products/… even when browsed inside a collection.
  • Responsive images with lazy loading; hero media loads first.

When adding content

  • Write a unique SEO title (under 60 characters) and description (under 155) in each product, collection and page's Search engine listing.
  • Add alt text to every image (describe the shirt, color and setting).
  • Keep one H1 per page. The product and collection title already are the H1; use H2–H3 in descriptions.
  • When changing a handle, keep Create a URL redirect checked.
  • Compress images before upload; aim for under 500 KB. Use .mp4 for hero videos and add a poster image.

Accessibility

Accessibility issues found by axe and Lighthouse were fixed before launch. To keep it that way, use real headings, write link text that makes sense alone ("Shop Western Yoke", not "Click here"), and keep text contrast on images readable.

Troubleshooting

Common issues, what causes them and how to fix them.

Product pages

Color swatches are missing

  • Fewer than 2 siblings were found. Check the product is in its family collection and custom.sibling_collection is set.
  • Sibling products have no custom.print image and no featured image.
  • Show sibling swatches is off in that template's variant picker.

Swatches show the wrong products

The shopper came from a broad collection, so its products show (up to 24). This is expected. From /collections/polos the theme uses best-sellers or the family instead.

Breadcrumb says "Shop" instead of the collection

The shopper did not arrive through a collection URL (search, email, ad). Expected behavior.

Size chart link is missing

The variant picker has no Size chart → Page chosen, or the option is not named Size.

Find my size link is missing

The WAIR app embed is off, or WAIR has no profile for this product.

Callout photo shows another product's image

The product is not in the callout photo map. Ask a developer to add it.

Collections

A filter value is missing

Check Hidden filter values, then the filter in Search & Discovery.

Product count shows "[collection_count]"

The token was used outside a collection page. It only works there.

Editor & deployment

My editor change disappeared

A developer pushed an older version of the template to GitHub. Find your change in the GitHub history ("Update from Shopify" commit) and restore it.

Spacing setting does nothing

Check both desktop and mobile padding values. If it still does nothing, custom CSS is overriding it; ask a developer.

Block says "app not found"

The app was uninstalled or its embed is off. Remove the block or re-enable the app.

Site-wide

Headings show in the wrong font

The Adobe Fonts kit is not loading. Check the kit's domain list includes the store domain.

Chat link does nothing

The Slide AI chat embed is off or still loading.

Store shows Closed during open hours

The hours line is not in the expected format (Wed – Thu: 11:00am – 7:00pm). Status uses Central Time.

Page is slow

Check image sizes first, then recently installed apps. Each app embed adds script. Use Lighthouse or Analytics → Web performance.

Developer rules

Conventions for anyone changing the theme code. They keep the site editable and upgradeable.

1. Horizon sections first

Build pages from existing sections, groups and theme blocks in JSON templates. Do not create new sections to match a design. If a section is close but missing a control, extend its schema.

// ❌ new custom section
"type": "io-brand-ethos"

// ✅ Horizon section + groups + theme blocks
"type": "section",
"blocks": { "group_1": { "type": "group", ... } }

2. Settings over CSS

Every section has desktop and mobile padding settings wired through spacing-style. Do not set padding, margin, gap, max-width or flex-direction in CSS. When CSS is unavoidable, add a Custom class to a group and scope the CSS to it.

/* ✅ scoped to the group hook */
.io-reviews-row .group-block-content { ... }

/* ❌ fights settings */
.section-wrapper, .hero { padding: 0; }

3. Match button heights

.button, secondary buttons, Shop Pay, Add to cart, the quantity selector and text size pills must all be the same height. Change sizing only through the button tokens from Theme settings (--button-padding-block, --button-font-size…) and keep --height-buy-buttons equal to the computed button height. Color swatches stay squares and are not stretched.

4. Old theme is reference only

The previous live theme is kept for behavior reference (apps, size charts, swatches). Do not copy its Liquid or CSS into this theme.

When to call a developer

  • A new section type or a layout settings cannot reach.
  • Adding a polo family to the swatch logic or a product to the callout photo map.
  • Changing chat hours, store timezone or contact page behavior.
  • Upgrading Horizon to a new version (custom changes must be merged by hand).
  • Replacing an app that the theme hooks into (Slide, Ryzo, WAIR, Judge.me).

Routine maintenance

A light checklist to keep the store healthy after launch.

Monthly

  • Click through home, a collection, a product, cart and checkout on phone and desktop.
  • Check Online Store → Themes for app notices and review new app updates.
  • Look for broken links in menus and the mega menu feature cards after products or collections are removed.
  • Check the Judge.me, Klaviyo and Slide dashboards for errors.

Quarterly

  • Duplicate the live theme as a dated backup.
  • Run Lighthouse on home, collection and product pages.
  • Review staff accounts and remove unused apps.
  • Confirm the Adobe Fonts kit and domain are active.

Before a campaign

  • Build new landing pages on a duplicated template, preview, then publish.
  • Update the announcement bar, hero slides and mega menu feature cards.
  • Check store location hours and holiday notes.
